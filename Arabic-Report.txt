- attendance_records, absence_followups

### سياسات الحذف حسب الدور:
- **coach**: never delete (restrictive policy blocks all deletes)
- **admin**: delete reviewed reports only (`is_finalized and status = 'reviewed'`)
- **manager**: delete any finalized report of institution
- **owner**: never delete (no institution scope)

### Storage policies:
- **trainer-avatars**: read for owner+platform+institution, write for owning user in own folder
- **trainer-medical**: read/delete for institution admins only, own institution folder
- **trainer-media**: read/delete for conversation members only (folder: institution/conversation/user)
- **trainer-report-templates**: read for institution members, write for admins only

## 6. حالة إرسال التقارير وحفظ التفاصيل والإشعارات

- **تدفق الإرسال**: draft → details → finalize (متتالية، لا يمكن العودة للخلف)
- **حفظ المسودة**: يتحقق من affected rows، يعيد insertion إذا vanished the draft
- **تفاصيل التلاميذ**: تُحفظ مع التقرير، rows المستنفدة تُحذف قبل insertion الجديدة
- **الرسائل الإشعار**: تُرسل للإدارة عند تقديم تقرير نهائي (`daily_report_notify` trigger)
- **حذف التقرير**: يظهر نجاح حقيقي فقط إذا تم حذف صف، وإلا ظهرت رسالة Errorvisible
- **`submitted_at`**: NULL للمسودات، مُعين من قاعدة البيانات عند finalization (لا يقبل من المتصفح)
- **حذف التفاصيل القديمة**: يتم قبل insertion الجديدة لتجنب فقدان البيانات
